# 本机版本升级入口

日常启动：双击项目根目录的 `EmergentInc_UI.bat`。它只启动已批准的冻结 Release；更新源码不会自动升级运行实例。

查看当前版本：在项目目录运行 `node scripts/version-upgrade.mjs status`，或 `EmergentInc_Upgrade.bat status`。G0007 是谱系代号，V24 是产品版本，两者不是同一编号。

## 各版本使用哪个入口

| 当前状态 / 目标 | 入口 | 用途 |
| --- | --- | --- |
| 新安装，空 Workspace | `EmergentInc_UI.bat` | 初始化并启动；不能用来覆盖已有数据 |
| V21 → V22 | `scripts/life-migrate.mjs` | 停机后的显式 Lineage / Current 数据迁移；不是完整发布器 |
| V22 内的本机软件版本更新 | `scripts/local-upgrade.mjs` | prepare / apply / recover，使用旧 Workspace 布局 |
| V22 → V23 | `scripts/v23-migration-dry-run.mjs` + `scripts/v23-upgrade.mjs` | 先离线备份演练，再 prepare / approve / apply，迁移为多 World 布局 |
| V23 → V24，以及保持 V23 Workspace 布局的后续软件版本 | **`EmergentInc_Upgrade.bat` / `scripts/version-upgrade.mjs`** | 冻结完整 Owner 软件版本、校验、准确哈希批准、全 World 切换与恢复 |
| World 的能力进化 / Gene 提案 | `/GENE` 的提案方向审批 + `scripts/v23-generation.mjs` | submit / validate / approve / birth；继续禁止修改 Root / Supervisor |

每次软件升级使用同一个入口，无须为 V25、V26 分别新建启动器。若将来改变 Workspace 布局，必须先提供明确的数据迁移器，不能直接套用版本标签。

## V24 及后续软件升级

本机网页入口：`http://127.0.0.1:8766/`。日常启动器自动启动独立维护页面；QIAN / YUAN / GENE 顶部的“发布升级”链接也通往这里。使用同一 Owner 口令、独立登录会话。点击提交仅展示目标，点击“准备 + 校验 + 批准并发布”才执行完整流程；页面在主服务重启期间保留进度。失败不自动重试，可在页面检查并恢复中断的升级。

Git 以 main 的第一父提交历史为主干，本地临时分支和远端分支显示为分叉卡片，包含分叉基点、最新提交与分支历史。基点不在当前主干窗口内的分支单独标注。仅统计本地、远端分支及标签，不计入工具内部检查点、准备结果及废弃分支的恢复引用。main 指针不等于已发布版本，实际运行版本及源码提交独立显示。

8766 是独立维护服务，启动时加载与其服务端配套的本地维护页面；8765 只运行已批准的冻结 Release。因此维护页面可能先于运行版本显示新功能，这不是开发代码绕过审批进入运行实例。修改维护服务脚本或页面后需要重启 8766；普通软件发布只切换 8765，源码切换期间正在运行的维护服务及其页面保持配套。

选择临时分支提交后，按钮将目标改动与当时的 main 合并，在不改变工作目录的情况下生成准确合并提交；冲突展示文件并停止。选择 main 主干的旧提交时，新增一个源码树与旧提交一致、父提交为当前 main 的回退提交，保留之后的 Git 历史。完整测试针对生成的结果运行一次；通过后自动批准该准确候选 Hash 并发布。发布仍执行现有数据兼容检查、隔离烟测及真实服务健康检查；旧代码不兼容现有账本或任务结构时拒绝切换，不恢复旧业务数据库。

成功发布后，main 快进到已发布的合并或回退提交，当前工作目录同步签出 main。有未提交修改、其他工作区签出 main、操作期间 main 或当前签出变化时拒绝同步。若软件已经发布但同步失败，页面明确显示该状态，只允许显式完成 main 同步或恢复，不能重复发布。现有本地 develop 只有在全部提交均已包含于 main、且没有其他工作区签出它时才自动移除；未包含的工作保留为临时分支。远端不自动推送或改写。

“删除分支及提交”仅允许选择指向该准确提交的本地非 main 分支；保护所有正在签出的分支，以及 main、当前 HEAD、已知实际运行提交及其祖先。多个本地分支指向同一提交时需选定一个。删除前确认，原子核对分支指针并保留内部恢复引用；不强制清除 Git 对象，不删除远端、标签、冻结 Release、发布记录或业务数据。提交仍被其他可见引用持有时仍显示在图中。

“删除分支及提交”旁的“立即回退”仅当所选提交对应一个仍在发布链上、可回退的已发布版本时可用；其他提交显示为置灰不可点击。回退沿用顶部快速回退的确认与后端校验，保留业务数据，不改写 Git 历史。

Bases outside the visible trunk window are labeled separately. Internal checkpoint, preparation and discarded-branch recovery refs are excluded; local/remote branches and tags remain visible. The running release and source commit are displayed independently from main. Selecting a commit is read-only. One button merges the selected changes into main, validates the exact generated result once, approves its exact candidate hash and publishes it. Selecting an older main commit creates a new commit with the historical source tree and current main as its parent, retaining Git history and current business data. Conflicts stop before validation/publication and show the affected files. Existing compatibility checks, isolated smoke tests and actual server health checks remain required; incompatible old code is refused without restoring old business databases.

After successful publication, main fast-forwards to the published result and the working directory switches to main. Dirty work, main checked out elsewhere, or concurrent checkout/ref changes are refused. If publication succeeded but Git sync did not, an explicit sync retry completes only Git sync without republishing. Local develop is removed only when main retains all its commits and no other worktree checks it out; otherwise it remains temporary. Remotes are never automatically pushed or rewritten. Deletion requires confirmation and removes only one selected non-main local branch at its exact expected tip. Checked-out branches and ancestors of main, HEAD and the known running source are protected. Recovery refs retain objects; remotes, tags, frozen releases, publication records and business data are preserved. Commits referenced elsewhere remain visible. The "Roll back now" button next to branch deletion is enabled only when the selected commit belongs to a still-eligible published version on the release ancestry; every other commit leaves it greyed out. It reuses the same confirmation and server checks as the rollback selector, keeps business data and never rewrites Git history. The independent 8766 service loads its matching maintenance page at startup; restart 8766 after server or page changes. Source checkout does not replace the UI of the running maintenance process; ordinary software publication switches only 8765.

维护页面绑定 `127.0.0.1`，端口为配置中主服务端口加 1。只执行既有升级器的固定操作，不接受命令或任意文件路径；普通 World / Agent 接口仍不能批准软件版本。启动维护页不会发布版本。

在项目根目录的 PowerShell 运行。源码必须已提交且工作区干净；使用 Node.js 24 和本机 pnpm。配置从 `.env` 的 `EMERGENTINC_LOCAL_EVOLUTION_CONFIG` 读取。

```powershell
.\EmergentInc_Upgrade.bat status
.\EmergentInc_Upgrade.bat prepare v24 "Owner 明确升级 V24"
# 阅读输出：候选 id、source_commit、gene_hash、candidate_release_hash、candidate_hash
.\EmergentInc_Upgrade.bat show <候选id>
.\EmergentInc_Upgrade.bat approve <候选id> <准确candidate_hash>
.\EmergentInc_Upgrade.bat apply <候选id>
.\EmergentInc_Upgrade.bat status
```

prepare 不切换服务；approve 绑定准确候选哈希；apply 暂停业务、快照数据库、迁移所有 Current，在隔离 Workspace 烟测，通过后切换、检查健康并恢复业务。订单、付款、World 私有数据和谱系保留。

Owner 软件维护不调用模型。未整理事实保留在旧代 Current 及带 SHA-256 的快照里，Lineage 明确记录 `OWNER_MAINTENANCE_DREAM_DEFERRED`；没有生成虚假 COMPLETED Dream。它们不会自动变成新代记忆，后续整理必须另行配置模型并处理存档。普通 Gene 出生仍必须完成 Final Dream。

```powershell
.\EmergentInc_Upgrade.bat rollback <已出生候选id> "回退原因"
.\EmergentInc_Upgrade.bat recover
```

V24 收款数据库是 schema 3。V23 只支持 schema 2：没有实例发票 / 收据 / 收入时，可以保留所有历史行并逆迁移后回退；已有任何实例发票，即使未付款，也拒绝直接退回 V23。后续应修复 V24 或使用兼容 schema 3 的已批准版本。不得用旧数据库备份覆盖新业务事实。

## 打开哪个页面

- `http://127.0.0.1:8765/`：所有人物和 World 共用的对外页面。
- `http://127.0.0.1:8765/GENE`：Owner 管理、公共网站配置、产品与实例订单 / 收入。
- `http://127.0.0.1:8765/QIAN`：人物。
- `http://127.0.0.1:8765/YUAN`：World。

这些是同一个已批准实例的不同页面入口，不是不同软件版本。

## QIAN 对话入口无限能量

人物“…”菜单中的“无限能量”默认关闭。开启后仅该人物当前对话入口享有自动补能，更换入口后授权随入口变化。入口在运行、模型结算或自主转账/繁衍时余额不足，会恢复到初始 100,000 Energy；需求更高时补足该动作所需余额，每笔自动补充记录为 `owner_infinite_energy` 外部奖励。Run Token 预算、实际调用计费、退款赤字及失活限制继续有效。

其他元胞不自动补能；入口根据成本收益自主决定是否通过既有邻居转账机制输送能量。能量不足的对话提示为“元胞能量不足，等待补充后重试。”；其他暂停原因保留独立状态。开关只改变补能授权，下一次运行会处理已有等待消息，不自动启动新 Run。
