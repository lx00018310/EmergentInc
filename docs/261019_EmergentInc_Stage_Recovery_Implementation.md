普通检查首期只支持可程序核对的文字包含及最少 UTF-8 字节数，阈值为 70%、80%、100%。这不能代替内容质量判断、付款证明或外部事实核验。旧计划没有普通策略时仍按原严格要求执行。

## 老板续办

在 BOSS → 视察公司 → 对应任务的环节进度中处理。服务端每次重算可用动作，并绑定目标 revision、计划 revision 及事实 hash。

1. 补充资料后，资料以“老板提供、待核实”来源保存；再明确选择继续。最近两条完整资料可用进度工具读取，较早内容仍保留在事件历史。
2. 调整普通清单或通过比例不会修改原目标规格。改变允许缺失的前置输入，须重新批准新版计划。
3. 追加调用数、时间或缺口次数必须给出有限增量，原请求重复只生效一次。额度不足时不能靠重开、返工或重启清零。
4. 跳过只改变普通节点及汇总结果，不修改旧 Attempt 终态、不添加证据、不增加成功次数。接受部分结果时明确按部分完成结案。
5. 公司 OFF、目标暂停、未知费用及未知外部结果仍由原控制权威处理。补料或保存决定不会自动打开公司。

## Review 发现与修正

- 路由允许字段与服务白名单不一致：在路由校验后剥离动作名，非法字段继续拒绝。
- 真实派工在创建 Attempt 前受额度拒绝：节点现在收敛到可见受阻状态，独立节点继续。
- 回执已收、进度保存失败：派工收口、节点 outcome 与 Goal 汇总放入同一事务，失败回滚后复用已付费结果。
- 获得授权后、真正派发前时间刚好耗尽：先检查剩余时间再写 SENT/STARTED；确定未发出的操作不误标 UNKNOWN。
- 旧执行模式没有 Worker 核验表：概览只在核验服务存在时读取，保留旧模式的故障隔离。
- 交付返工刚写入说明便生成结案提案：现在等待新执行结果；旧提案保持 REJECTED，新结果绑定新版计划及缺口快照。
- BOSS stale revision 与丢失响应：确定拒绝保留草稿并刷新事实；响应不明时仅重试原字段及原幂等键。
- 窄容器的依赖勾选项布局：修正为文字旁的自然宽度复选框；中文和英文同步检查。
