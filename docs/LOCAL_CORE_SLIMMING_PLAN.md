# 本地元胞演化与交付物闭环：精简实施计划

日期：2026-09-16  
状态：范围已确认，待实施；本文不代表代码已修改或运行已验收。

## 1. 已确认目标

先跑通本地元胞演化与交付物闭环，后续能力一步一步增加。

唯一主路径：

```text
打开 UI → 设置创世提示词 / 本地环境 → 设置轮数和预算 → 启动
  → 消费消息 → 调用模型 → 更新 pixel.md
  → 按需读取本地环境、复制、邻居通信 / 能量转移、读写本地交付物
  → 保存消息、账目和世界状态 → 显示结果 → 停止或继续
```

“本地”指业务动作和交付物在本地完成，模型推理仍使用现有 API。暂不包含业务联网、宿主代码执行、部署、支付或真实商业运营。

最小改动原则：沿用 V9 调度器、消息路由、SQLite 账本和现有 UI；断开支线调用及入口，不另造简化引擎，不增加插件框架或多模式切换系统，不批量删除旧代码。

## 2. 已核实的代码事实

| 位置 | 当前行为 | 对精简的影响 |
| --- | --- | --- |
| `emergentinc/ui/run_controller.py` | 正常 UI 运行进入 `V9RoundScheduler`；另有通过 MagicMock / `__wrapped__` 识别旧 runner 的分支 | 收敛为单一 V9 路径，测试改在 V9 边界注入 |
| `emergentinc/engine/runner.py`、`README.md` | 文档中的命令行运行入口使用旧 `RoundRunner` | 首阶段从快速上手移除旧运行命令，不为对齐 CLI 再重写一条流程 |
| `run_controller.py::_run_startup_audit` | 队列、未结预留、未知调用、Pixel 回合以及待审批请求均参与启动检查 | 删除审批前置依赖；保留直接影响当前数据和计费正确性的检查 |
| `scheduler.py` 的 owner_request 分支 | 创建 `PENDING_OWNER`，提交消息后立即结束本轮；位于工具、复制、路由之前 | 普通模型请求也能截断本地闭环，需断开整个审批支线 |
| `ui/loop_store.py` | Run 前后均创建快照；完成快照失败可将 Run 标为错误 | Run 生命周期从 Loop 分离，沿用 CoreStore 的 runs 表 |
| `engine/audit.py`、`ui/static/app.js` | 深度审计检查旧 Loop、账目等；前端反复请求并显示“启动已拦截” | 审计提示与后端启动规则并非同一套；停止主页面自动深度审计 |
| `engine/operations.py` | 支持本地 save/read/list；`run_isolated_code` 固定不可用 | 首阶段只暴露实际能用的三项工具 |
| `scheduler.py::_check_natural_wake` | 默认间隔 5 轮自然唤醒 | 空队列情况下“跑 1 轮”可能没有调用，首轮启动消息需明确 |
| `cli/init_workspace.py` | 从包含旧 genome 等文件的 bootstrap 复制初始状态 | 初始化也需收敛到 V9，不能只让已有工作区勉强可用 |

这是代码审阅结论；未在本轮启动服务、调用真实模型、改动运行数据或重跑测试。历史报告中的通过结果不作为本次验收证据。

审阅时已有未提交修改：`engine/router.py`、`ui/owner_bridge.py`、`tests/test_owner_approval_ui.py`，以及未跟踪目录 `.codex_test_owner_focus/`。实施前复核这些差异，不能覆盖、回退或当成垃圾清理。

## 3. 保留与暂时断开的边界

### 保留

- V9 三输入模型上下文、创世提示词和本地 environment 主动读取。
- Pixel 自我记忆、六邻域、复制、能量转移、零能量失活。
- SELF / 邻居 / STOP 消息路由、队列持久化与现有跳数、消息数限制。
- 本地 `save_artifact`、`read_artifact`、`list_artifacts`。
- 现有预算预留与实际用量结算、单次 Run 上限、全局累计上限及 Pixel 能量约束。第一阶段不改财务模型，不用无限预算掩盖问题。
- 开始、停止、继续运行、状态、地图和文件查看；保留真实调用数与空转结果区分。
- 工作区单进程锁、原子写入、凭据隔离、文件路径和 Pixel 所有权校验。

### 暂时断开

| 内容 | 具体处理 | 旧数据处理 |
| --- | --- | --- |
| Owner 审批 | 删除启动扫描和运行中停机分支；移除 UI 审批卡片、轮询及主服务审批路由注册 | 保留旧请求文件，不自动批准、不自动拒绝；不再阻断本地运行 |
| Loop、快照、分支、回滚 | 控制器不再初始化或调用 LoopStore；主页面移除 Loop 树；停用相关写接口 | 保留历史目录，不自动恢复、不删除 |
| 回款、退款、支付相关流程 | 移除主界面操作和主服务对应写接口 | 保留历史账目及底层函数，不改变余额 |
| 代码执行及外部能力 | 不向模型暴露不可用工具，不接入网络、部署、Shell 等动作 | 不自动授予权限或安装执行环境 |
| 全工作区深度审计与自动报告 | 退出主页面高频轮询及 Run 必经收尾；保留人工诊断能力 | 保留历史报告；旧支线异常不决定新 Run 的业务结果 |
| 旧版 V5/V8 实验入口 | 从当前快速上手和生产调度调用链中移除 | 代码暂存；不进行整库删除或目录搬迁 |

“暂时移除”在本阶段明确为断开主路径、停用入口并保留实现，便于逐项恢复；不能只隐藏按钮而让后端仍停机。

## 4. 实施顺序与文件范围

### P1：先断开审批和不可用能力

涉及 `engine/scheduler.py`、`engine/llm.py`、`resources/prompts/v9_system_prompt.md`、`resources/schemas/v9_pixel_response.schema.json`、`engine/operations.py`。

1. 提示词明确本期能力只有本地演化和三项文件工具，补全实际工具参数说明。
2. 为减少协议改动，首期保留 `owner_request` 字段但要求为 null；归一化阶段记录非空请求为“不支持的能力”，不生成审批单、不触发停机、不执行请求。不能因该字段丢弃同一响应中合法的本地动作。
3. 工具只允许 save/read/list；其他工具返回明确不可用回执，不转入审批，不自动尝试其他执行方式。
4. 保持现有复制、消息路由和结算顺序，不顺带重构调度器或增加通用容错层。

### P2：Run 脱离 Loop，启动规则收敛

涉及 `ui/run_controller.py`、`ui/api.py`、`ui/world_reader.py`，必要时少量调整 `engine/core_store.py` 的现有查询。

1. 控制器直接生成独立 run_id，在已有 runs 表登记、更新状态；一次用户启动对应一个 Run，所有轮次共用它。
2. 移除控制器对 LoopStore、启动/结束快照、旧 runner 测试识别分支的依赖。状态/API/UI 使用 run_id，不借用假的 Loop ID。
3. 初次建库时也先建立 Run；创建失败不得启动线程。异常后清理 running 状态，保留真实完成轮次、用量和错误。
4. 删除待审批请求启动拦截。历史 Loop、快照、旧报告不能影响启动或收尾。
5. 保留损坏队列、关键 Pixel 状态损坏、未结预留、未知计费和回合领先等核心检查。出现这些真实故障时显示具体文件或调用标识及原因，不能统一显示含糊“门禁”。
6. 深度审计不再作为 UI 启动裁决来源。预算不足由实际启动/调用检查给出具体不足类型，不能因历史审计的旧上限阻止提交新预算。
7. 沿用全局累计预算语义，不随 Run 重置已花费金额；UI 清楚标注“本次运行上限”和“累计总上限”。

说明：只删保护判断不能解决已有损坏数据。若实施时发现真实未结调用或状态破损，单独列出需恢复事项；不清空数据库、不补造余额、不自动重发结果未知的付费调用。

### P3：让新工作区的首次操作也能跑通

涉及 `cli/init_workspace.py`、必要的 bootstrap 文件及 `engine/scheduler.py`。

1. 沿用已有 V9 Pixel 初始化能力，建立 V9 state.json、pixel.md、本地环境和必要目录；初始化结果不能依赖用户再找旧版迁移命令。
2. 新工作区仅投递一次创世启动消息，保证“跑 1 轮”可真正调用模型。不得每次点击开始都重复注入消息。
3. 保留后续自然唤醒及 STOP 语义；没有模型调用时明确显示空闲，不通过强制持续唤醒制造活跃假象。
4. 非空工作区继续拒绝初始化覆盖。现有 V9 工作区原位使用；不在本次精简中自动迁移或重置旧实验数据。

### P4：收敛 UI，补上交付物查看

涉及 `ui/static/index.html`、`ui/static/app.js`、必要的 `style.css`、`ui/api.py`、`ui/world_reader.py`。

1. 保留轮数、预算、开始/停止、创世提示词、本地环境、运行结果及元胞地图。
2. 移除审批卡片、Loop 树、回款弹窗、支线指标，以及对应脚本加载、DOM 引用和轮询；不能删除 HTML 后遗留 JS 报错。
3. 主页面仅轮询世界和运行状态；预算摘要直接来自已有 Run 数据，不为显示剩余额度运行全库审计。
4. 复用现有文档弹窗，增加所选 Pixel 的本地交付物列表与文本读取；仅增加完成该查看操作必要的只读接口。沿用文件名和路径边界校验，不新增文件管理系统。
5. 显示完成轮数、实际模型调用数、消息处理数、用量及停止原因；交付物以磁盘实际文件为准，不以模型声称完成为准。

### P5：文档与验证

- 更新 README，只给出初始化、UI 启动和本地主路径操作；明确停用功能。
- 调整依赖旧 Loop / 审批的集成测试预期。旧模块独立测试可保留，不能用普遍 skip 隐藏回归。
- 不新增部署、打包、迁移平台或自动恢复框架。

## 5. 验收标准

以下为实施后的验收，不是本次已完成结果。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 空目录初始化 → UI 跑 1 轮 | V9 Pixel 可读；至少一次实际模拟提供方调用；完成状态和计数一致 |
| 环境 → 复制 → 消息 → 交付物 | 隔离测试中提供方按固定响应读取环境数字 42、复制邻居、发消息，由子代保存含 42 的文件；UI 可列出和读取 |
| 连续运行 10 轮，再运行 5 轮 | 两个独立 Run；世界轮次连续；累计用量不重置；无需审批或快照 |
| 模型返回 owner_request，同时返回合法文件操作 | 没有审批单或 OWNER_ACTION_REQUIRED；本地操作按协议执行，禁用能力有明确记录 |
| 工作区存在旧待审批和损坏的 Loop 历史 | 核心状态正常时可运行；历史文件不被修改 |
| 文件工具越界或代码执行请求 | 返回拒绝/不可用，不启动外部执行，不停止整个系统等待审批 |
| 用户停止、预算不足、供应商明确拒绝 | 状态准确，无后台继续新调用，无自动无限重试 |
| 结果未知、队列损坏 | 明确停止并定位原因；不伪造成功、不自动退款重试或清空队列 |
| 重启服务后继续 | 世界、已保存交付物和预算仍在，已提交消息不重复消费 |
| 浏览器实际操作 | 无缺失 DOM 错误，无旧审批/Loop/审计轮询；文件内容经过文本转义展示 |

复用现有 smoke、operations、消息恢复、能量守恒、预算、停止、无活动真实性及私密信息隔离测试；仅补上述主路径交叉场景。先定向回归，再运行完整测试套件确认改动边界。

Windows 验证命令示例：

```powershell
python -m pytest tests/test_smoke_v9.py tests/test_operations_artifacts.py tests/test_run_controller_stop.py tests/test_run_budget_end_to_end.py tests/test_no_activity_run_truthfulness.py -q
python -m pytest tests -q
```

模拟测试验证确定性流程；真实模型验收另以有限轮数和预算跑一次本地任务，记录真实调用及落盘文件。不能把模拟通过写成真实模型闭环通过，也不能要求随机模型每次都选择复制才能认定引擎正确。

## 6. 后续加回顺序

本期验收通过后，再按实际任务逐项增加，每次只恢复一条完整路径：

1. 有具体需求时接入业务只读联网能力。
2. 配置真实隔离环境后接入代码执行。
3. 接入部署等外部写动作，并只对该动作增加必要授权；普通本地演化不恢复全局审批阻断。
4. 有真实经营需求后恢复支付、回款和退款流程。
5. 确有实验对比需求后再恢复快照与分支；运行本身不依赖快照成功。

本期完成条件是“用户能启动、观察元胞演化、拿到本地文件并继续运行”，不是删除文件最多，也不是让所有异常都能强行继续。
