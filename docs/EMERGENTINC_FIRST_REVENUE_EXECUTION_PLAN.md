## 4. 失败处理和最小交接记录

### 4.1 只对有证据的失败采取对应动作

| 情况 | 应做 | 不应做 |
| --- | --- | --- |
| 原有暂存代码导致检查失败 | 定位并说明与本次修改的关系 | 回退或重写用户修改 |
| 工具同批首项失败 | 拆开任务，确认剩余项被跳过 | 改成忽略所有失败继续执行 |
| 临时/创世提示词未接通 | 使用已接通的 Mandate 并如实说明 | 为首发重构提示词系统 |
| 模型调用结算未知 | 暂停后续付费 Run，依据真实核验走现有恢复流程 | 默认当作未计费、删账或重试掩盖 |

| 服务/交易需要未知现实权限 | 完成具体材料，再问缺失项 | 用“批准继续”替代明确目标与动作 |
| 没有外部客户/支付 | 记录实际反馈，说明下一次获客试验 | 自己付款、编造转化率或直接奖励冒充收入 |
