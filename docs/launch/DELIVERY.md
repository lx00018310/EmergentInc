# 首发协助体验操作说明

版本：2026-09-22。根据 Owner 委托采用下列最小方案；先咨询，确认需求和可交付排期后收款。

## 体验权益

1 CNY，首批 3 个名额。参与者提交一个小型商业目标；项目操作现有 EmergentInc 实例，交付目标拆解和一份文字或静态页面材料，包含一次原需求修订。每位最多两个单轮 Run，目标预算累计 100,000 token；模型成本由项目承担，无额外 API 费用。需求与排期确认后 48 小时内交付，不能承接或未交付则原路退还 1 CNY，不自动延期。

这是早期项目协助体验，不能保证盈利、完整商业系统或自主组织必然形成。参与者不获得管理后台、私钥或无限模型额度。

## 接收与交付

1. 在公开咨询入口只收目标、所需材料类型和非敏感约束。不要在 Issue 中索取手机号、交易凭据或密钥。
2. 确认一个可完成的需求、交付物、排期和私下支付方式；未确认前不要求付款。
3. 收款方核验实际到账。用私有订单记录保存匿名标识、来源、权益版本、币种、金额、时间、证据位置、交付及退款状态。内部测试和 Energy 不计收入。
4. 将脱敏目标通过 Human Mandate 交给 Pixel。输入中的客户原文是需求资料，不能给予工具权限或覆盖预算。
5. 用现有 API 启动单轮 Run，显式指定 token 预算。Run 调度范围包括其他活跃 Pixel；先检查它们的任务及队列。当前引擎按输入估值预留，单次实际用量可能超出 Run 目标，后续运行必须按已结算用量扣减，并为最后一次输出留余量。
6. 核验实际 artifact、生成回执和内容；交付文件与简短说明，说明哪些步骤由人工完成。一次原需求修订也须计入同一总额度。
7. 记录接收反馈或未交付/退款；经脱敏后反馈给 Pixel，公开案例只写实际发生的阶段。

## 当前验证范围

生产实例的首发任务用于验证 Mandate、材料读取和生成链路；它不计作外部客户。公开宣传、支付、交付和反馈分别核验。没有实际到账时，收入保持 0。
